# Kako Mirror 改善案メモ

Date: 2026-05-28

## このメモの前提

このプロジェクトでは、ドキュメントが遅れているときは現在のアプリ実装を正と見ます。`docs/CHANGELOG.md` の新しい更新は、実装意図の補助情報として優先的に参照します。

そのため、改善案は「理想論」よりも、今のアプリの事実に合わせてドキュメントやコードを更新し続ける前提で整理します。

## 今回の判断を反映した優先順位

## A. すぐ進める項目

### 1. 古いドキュメントをアプリ実装に合わせて更新する

現状、`AGENTS.md`、`README.md`、`SPEC.md` に古い数値や説明が残っています。

今の実装と新しい `CHANGELOG` を見ると、少なくとも次は追従が必要です。

- 遅延上限は 10 秒ではなく 5 秒
- 初期遅延は 5 秒ではなく 2 秒
- バッファは 10 秒ではなく 5 秒
- 目標サンプリングは 15 fps ではなく 30 fps

やること:

- アプリ実装に合わせて `AGENTS.md`、`README.md`、`SPEC.md` を更新する
- 今後も docs が散らかるなら、重複説明を減らして `SPEC.md` 側へ寄せる

### 2. ローカライズ対応の土台作り

これは実作業として進める価値があります。

現状:

- `strings.xml` に基本ラベルはある
- ただし `MainScreen.kt` にコーチマーク文言、`LIVE`、`スキップ`、`次へ`、`OK`、秒表記など、visible text がまだ残っている

やること:

- 画面に出る文字列を `strings.xml` に寄せる
- 数値付き文言も resource ベースに寄せる
- `Locale.JAPAN` 固定のような箇所は、後で英語化しやすい形へ寄せる

狙い:

- 文言調整と UI 調整を分離する
- 後から `values-en` を足しやすくする

### 3. 設定バックアップ方針を明文化する

ここはユーザー判断が入ったので、提案ではなく反映対象です。

方針:

- アプリ設定のバックアップ / 端末移行は許容する
- カメラフレーム、写真、動画、レビュー情報は永続保存しないし、バックアップにも含めない

やること:

- manifest と backup rules を明示する
- `SPEC.md` と `AGENTS.md` にも設定のみ許容と書く

### 4. カメラ起動失敗時の導線を設計する

これは分岐を増やすだけでは足りません。失敗後にユーザーが取れる行動まで必要です。

最低限ほしいフォロー:

- 権限未許可:
  - 権限を許可してください
  - 再試行ボタン
  - 必要なら設定アプリを開く案内
- 前面カメラなし / 利用不可:
  - この端末では前面カメラを使えません
  - 対応端末で使ってください、という明確な説明
- カメラ占有や一時失敗:
  - 他のカメラアプリを閉じて再試行してください
  - 再試行ボタン

重要:

- ただエラーメッセージを出すだけだと「で、どうすればいいの」で終わる
- 分類と再試行導線はセットで考える

## B. 方針はあるが、やり方を限定する項目

### 5. フレーム処理の改善は最適化止まりにする

発熱対策として 10 秒保存をやめ、最大 5 秒にした経緯があります。ここは尊重すべきです。

注意点:

- フレームレートを落とす
- 画質を落とす
- 遅延ミラーの見え方が不自然になる

こうした方向は、レビューやストア評価で「画質が悪い」「使えない」で切られる危険があります。

したがって今の改善方針は:

- 品質を下げる変更は避ける
- CPU / メモリ / GC の無駄を減らす最適化に留める
- まずは計測して、劣化なしで削れるコストだけ削る

### 6. ズームアウト値は今の実装を前提に据える

以前の改善案では、1.0 未満ズームの永続化を問題候補に挙げましたが、この件は今の実装を正として扱います。

今すぐの改善項目にはしません。

扱い:

- 実機で再現する不具合が出ない限り、優先修正対象にしない
- 先に docs の更新と localization 基盤を進める

## C. 今は保留する項目

### 7. アクセシビリティ強化

必要性はあるものの、今は保留です。

対象候補:

- semantics
- contentDescription
- TalkBack 対応
- カスタムタッチ領域の整備

ただし、ローカライズ基盤とドキュメント修正を先に終えてから着手します。

### 8. テスト拡充、実機QA整理、ドキュメント運用ルール化

これらは重要ですが、今は後ろに置きます。

後回しにするもの:

- `MainScreenViewModel` のテスト拡充
- 実機QAチェックリストの整理
- 監査ドキュメントの運用ルール化

補足:

- ただし docs の鮮度自体は今すぐ維持が必要です
- 運用をルール化するのは後でも、実際の文書更新は泥臭く続ける必要があります

## このメモの今の着地

現時点の優先順は次です。

1. アプリ実装に合わせて `AGENTS.md` / `README.md` / `SPEC.md` を更新する
2. visible text を resource 化してローカライズ土台を作る
3. 設定バックアップの許容範囲をコードと文書に反映する
4. カメラ起動失敗時の「次にどうすればいいか」まで含む導線を設計する
5. フレーム処理は品質を落とさない最適化だけ検討する

それ以外の改善は、上の作業が落ち着いてから進めます。
